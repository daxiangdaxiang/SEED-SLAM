# Lazy Refresh: Transfer and Measurement-Stress Audit

## Purpose and Setting

This stage tests the existing historical-model refresh policy, not a new robust
estimator. No estimator source, noise parameter, topology, PCG budget, robust
kernel, covariance fit, or identity rule changes. The executable is identical to
the preceding D4/D9 full-window experiment. Only experiment input support and
posthoc diagnostics were added.

D2 and D3 were used in earlier backend research, but not to design this refresh
policy. They are transfer checks, not untouched final test sets. Each uses the
existing chain 1-2-3-4-5, known barcode identities, native bearing/range factors,
one root gauge, and a common past-only state. The bootstrap is generated by the
unchanged causal `joint_cached` replay at first complete chain support:

| Case | Prefix cutoff s | Bootstrap service s | Bootstrap application MB | Suffix frames | Prefix/final factors |
| --- | ---: | ---: | ---: | ---: | ---: |
| D2 | 21.877000093460083 | 0.3884 | 4.777944 | 1222 | 597 / 3538 |
| D3 | 67.76399993896484 | 4.7345 | 17.867136 | 777 | 2503 / 4444 |

Both stop at global elapsed 120 s. Bootstrap service and communication are
excluded from the suffix tables for both arms; offline package-export work is
also excluded. The packages are not completed to nonlinear convergence. D3's
initial physical loss is 2150.235632, versus D2's 131.699525. This is a
common-past-conditioned comparison, not an unbiased end-to-end initialization
ranking. There is no GT-assisted initialization.

Four predeclared cases use normal-equation `joint_cached_one` with ordinary
1e-4 chart refresh (reference) or the existing `--lazy-refresh` policy (candidate).
Each runs sequentially in ABBA order with two timing repetitions. Every suffix
frame uses exactly one interface PCG iteration. No additional completion solve
is performed. Sixteen suffix processes and two bootstrap processes finish
successfully within their watchdogs. GT evaluation runs only after the estimator
processes for each comparison terminate and does not select subsequent cases.

For D2 stress cases, only suffix bearing measurements change, seed 20261003:

- Gaussian: independent additive SD 0.15 rad, wrapped on the circle, on all 1719
  suffix observations. The estimator's bearing SD remains 0.05 rad.
- Sparse: independently selected probability 0.05, signed 0.5 rad offset. This
  realization changes 83/1719 observations (4.83%), in 81 frames.

The prefix is byte-identical; timestamps, odometry, ranges, identities, and
factor counts are unchanged. No fault labels are given to the estimator.
These conditions are artificial diagnostics, not claims about actual MR.CLAM
noise. One seed is not a statistical robustness evaluation.

## What the Stress Test Actually Establishes

The optimizer speedup transfers to these noisy inputs, but it does not confer
statistical robustness. Lazy causal RMSE rises from 0.296666 m on original D2 to
0.402228 m under Gaussian corruption (+35.6%) and 0.326726 m under sparse
corruption (+10.1%). Ordinary refresh exhibits essentially the same worsening.
Therefore switching back to the more frequent refresh policy is not sufficient
to repair these cases. This does not rule out other finite-iteration effects or
prove that a specific adaptive likelihood will solve them.

Importantly, sparse corruption improves the aggregate *final* trajectory and
object RMSE in this realization, while worsening causal trajectory RMSE. This
result is not suppressed. Random perturbations, trajectory deformation, final
smoothing, and alignment can produce different metric orderings. A single
better terminal ATE is not evidence of fault handling.

| Case | Lazy refresh requests | Non-updating frames | Next-frame full-step recoveries |
| --- | ---: | ---: | ---: |
| D2 original | 32 | 5 | 32 / 32 |
| D3 original | 16 | 2 | 16 / 16 |
| D2 Gaussian | 29 | 4 | 29 / 29 |
| D2 sparse | 39 | 6 | 39 / 39 |

All non-updating frames are isolated. All requests are serviced next frame;
there is no terminal pending refresh. These recoveries include newly arrived
data and are not controlled same-graph causal attribution experiments.

Gaussian corruption worsens causal error while reducing requests from 32 to 29.
More strikingly, all 81 frames containing the sparse injected errors accept
their full step with positive model prediction and positive actual decrease;
none requests refresh on that frame. All 83 corrupted factors remain in the
graph. The 39 requests occur on other frames, possibly with indirect historical
effects. This is not a failed detector score: the refresh policy was never a
measurement-validity classifier. It shows why it must not be repurposed as one.

### A Simple Explanation

The refresh test compares a quadratic approximation with the *specified*
physical objective. It asks whether the old local model still predicts useful
optimization work, not whether the specified likelihood describes the sensor.

For example, let the true scalar state be 0, with one correct observation 0 and
one corrupted observation 10, equally weighted:

```text
F(x) = 0.5*x^2 + 0.5*(x - 10)^2.
```

From x=0, the exact Newton step moves to x=5. Predicted and actual decreases are
both 25, so the quadratic model is perfect and no refresh is needed. Nevertheless
the state moves away from truth. Better model fidelity cannot by itself repair
the wrong statistical compromise. This elementary example explains the observed
separation without inventing a new gate.

## Research Decision

Retain the lazy policy as a computational candidate and freeze its settings.
It now has supporting evidence on four original sequences (D2/D3 here, D4/D9
previously), but neither general convergence nor production readiness is shown.
Do not add more refresh thresholds in an attempt to detect bad observations.

The next statistical gate should first measure an oracle-calibration gap on the
same fixed corruption streams: known added Gaussian variance versus nominal
variance, before attempting to learn it online. Separately test sparse-fault
treatment rather than absorbing every fault into one global covariance. Oracle
information must remain explicitly diagnostic and never be reported as an
adaptive method. The earlier D1-to-D4 covariance-transfer failure remains
unresolved; repeated residual fitting is not justified by this result.

If a better noise model does not improve causal state quality even under the
oracle diagnostic, investigate state/noise identifiability and finite-response
error before implementing a richer learner. If it does, the open problem is
estimating that correction from available past data without confusing solver
lag with sensor variance. Worst-frame backtracking remains a separate optimizer
problem; it is not evidence that a new robust kernel is needed.

## Verification and Artifacts

62 native C++ tests and 102 Python tests pass. New tests cover explicit input
selection, exact prefix/future preservation, seeded causal perturbations,
unchanged non-bearing fields, and grouping fault labels by frames rather than
observation count. Existing tests cover gauge, consensus, causal replay,
conditional/normal parity, and deferred refresh behavior. No C++ rebuild was
necessary because the estimator source and executable are unchanged.

The native fixed-gauge relative step error is 1.13e-16; full linear residual is
3.25e-16; matrix-free product error is 3.53e-17. The routed unit test uses six
PCG iterations and verifies relative residual 1.98e-16. Experiment suffixes use
one PCG iteration per frame (1222 for D2, 777 for D3), with maximum relative
residuals as high as 2.63: do not call those linear solves converged. MPI is not
run (0 ranks). CCI/D-CCI and production DBA-DRANPP remain unchanged.
