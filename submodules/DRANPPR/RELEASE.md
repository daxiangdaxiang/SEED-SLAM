# DRANPPR Experimental Snapshot

Version: `v0.1.0-dranppr.1`. This is a research checkpoint, not a stable release.
The inherited README below this directory describes the earlier DBA snapshot;
this document is the authoritative entry point for the new research package.

## Algorithm Map

| Layer | Implementation | Scope |
| --- | --- | --- |
| Persistent local factors and incremental models | `include/DPGO/Incremental*`, `src/Incremental*` | Optional native research |
| Local nonlinear physical response and interfaces | `src/Native*`, `experiments/native_local/` | Native Pose2/Point2 replay; separate SE3 calibration controls |
| Noise-calibration research | `scripts/dranppr_*`, `experiments/network_noise_*` | Independent calibration evidence; not a general robustness guarantee |
| Asynchronous fixed-model updates | `experiments/async_interface.py` | Known delay contract, immutable charts/rows, routed simulated network |
| Error-aware step strength | `experiments/prediction_error_budget.py` | Causal empirical horizon-specific error, not a certified future bound |
| Finite model response | `experiments/quadratic_response.py` | Optional corrected/frozen forcing predictor with charged model packets |
| Evidence and independent review | `experiments/audit_model_response.py`, `review_model_response.py` | Objective/step/traffic auditing, not ATE evaluation |

The strongest current communication reference is `budget_hold`. The
`model_response` candidate improves its frozen-forcing ablation, but uses too
many extra bytes to beat adaptive hold. There is no change to the existing
SEED-SLAM DBA package or its defaults.

## Self-Contained Experiment

From the SEED-SLAM repository root, use Python 3.9 and the pinned requirements:

```sh
python3 -m pip install -r releases/dranppr-requirements.txt
bash scripts/test_dranppr_python.sh
bash scripts/reproduce_dranppr.sh
```

Outputs are created under this package's ignored `results/release/`. Existing
outputs are not overwritten. Use `bash scripts/reproduce_dranppr.sh results/new`
for another run. All scalar model fixtures are self-contained under
`fixtures/interface_models/`, including physical Pose2/Point2-derived and
synthetic SE3-derived quadratics. These are not raw sensor datasets.

The result is 40 stress runs plus 100 ordinary-network runs, with independent
review archives. `evidence/reference/` contains the original local summaries
and audits. `ORIGINAL_ARCHIVE_SHA256SUMS.txt` records their full historical
archive provenance, not a claim that all original traces are included here.
Fresh traces and their own checksums are generated by the reproduction command
and distributed as the prerelease evidence asset.

`SOURCE_SHA256SUMS` verifies the packaged source/fixtures/reference records.
`SNAPSHOT.json` records the inherited base commit plus individual working-file
hashes. The base commit alone does not identify the uncommitted research code.
Historical documents may refer to old local paths or unpublished larger data;
those workflows are not the self-contained release reproduction path.

## Optional Native Build

The fixed-quadratic experiment above does not require GTSAM or a C++ build.
For native research targets, install the normal DPGO dependencies and a matching
GTSAM development package. The audited GTSAM fork is `DanMcGann/gtsam`, commit
`03c263fe08b02c90a8861d36f77422765d39506d`. Match its Eigen allocation ABI and
compiler flags; see `docs/dranppr_native_local_model_report_20260922.md`.

From this package directory, set paths to your own GTSAM installation:

```sh
cmake -S . -B build/native -DCMAKE_BUILD_TYPE=Release \
  -DBUILD_DPGO_NATIVE_MODEL=ON -DBUILD_DPGO_TESTS=ON \
  -DGTSAM_DIR="$GTSAM_DIR" -DGTSAM_INCLUDE_DIR="$GTSAM_INCLUDE_DIR"
cmake --build build/native --target testIncrementalLocalModel native-joint-audit native-joint-replay native-pose3-calibration-audit -j2
build/native/bin/testIncrementalLocalModel
```

Native Python integration tests have separate binary environment variables;
the historical `/tmp` defaults are not portable. For example:

```sh
export DRANPPR_NATIVE_JOINT_BINARY="$PWD/build/native/bin/native-joint-audit"
env PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python3 -m pytest -q tests/test_native_joint_audit.py
```

The new asynchronous predictor is **not** wired into this native nonlinear
backend. The SE3 fixture results cannot be advertised as native online SE3
or a new riMESA/ATE comparison. The production legacy targets also retain the
preexisting limitations documented in the inherited README.
